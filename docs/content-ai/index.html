content-ai

A pluggable substrate for AI-assisted content suggestion: fill entities from sources, refine them field-by-field, and orchestrate full refreshes — while your app keeps ownership of storage, review, and side effects.

@pixelmord/content-ai-core @pixelmord/content-ai-ingest @pixelmord/content-ai-refine

The seam: what you supply, what the substrate owns

This is the one idea to hold onto. The runners are pure orchestration — they never touch your store or event log. You hand them a description of your entity and a strategy for writing results back; they hand you suggestions, auto-applied values, and trace records. Every I/O boundary stays in your code (ADR 0017, ADR 0020).

source-driven

runFill

Populate many fields from one artifact in a single call. Also the path for translation.

prompt-driven

runRefine

Generate or improve specific fields from current data + prompts. One LLM call per field.

orchestrated

runRefresh

Compute targets, drive runRefine, and write back through your assemble strategy.

The three packages

content-ai-core

imported by everything

The shared substrate: contract types, the append-only event log + suppression, fingerprinting, the provider factory + tracing middleware (/server), and presentation helpers. No runner of its own.

content-ai-ingest

runFill

Source-driven fill. Turns a PDF, image, text, URL, or sibling-locale entity into per-field suggestions in one model call.

content-ai-refine

runRefine · runRefresh

Prompt-driven per-field refinement and the refresh orchestration that drives it through your per-kind strategy.

Install

Published to the GitHub Packages registry under the @pixelmord scope. 

# .npmrc → @pixelmord:registry=https://npm.pkg.github.com
pnpm add @pixelmord/content-ai-core \
         @pixelmord/content-ai-ingest \
         @pixelmord/content-ai-refine

core is a peer of both runners — install it alongside. Server-only entry points (/server, /testing) use node:async_hooks and must not be bundled for the browser.
